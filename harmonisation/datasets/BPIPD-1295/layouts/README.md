# Fixed-width layouts for BPIPD-1295 (High School and Beyond)

The 1980 base-year files (ICPSR 07896) and 1982 first follow-up files (ICPSR 08297) are headerless fixed-width ASCII files with one line per case.
Each layout CSV here gives the column positions for one of them, and `dataset.yaml` points the matching `fwf` resource at it through `col_positions`.
All nine layouts are generated by `generate_layouts.R` from the study's own SPSS setup files; none was written by hand.

## Columns

| Column | Meaning |
|--------|---------|
| `name` | Variable name exactly as the setup's DATA LIST gives it. |
| `start`, `end` | 1-based, inclusive character positions from the DATA LIST. |
| `type` | `c` for identifiers (`ID`, `CASEID`, `SCHLID`, `SCHOOLID`, `STUDNTID`, `TEACHID`, `FAMID`, `FSCHID`, `CONSCHID`), alphanumeric `(A)` fields and numeric fields whose values are not all numbers; `d` for every other field. |
| `decimals` | The decimal count the setup declares (`(n)` after the column range), kept verbatim for provenance. |
| `rescale_decimals` | The power of ten the tidier must divide the field by to put it on its documented scale; blank means the value is already on its scale. See "Decimals" below. |
| `setup_block` | Which DATA LIST block of the setup file defines the field (1 for single-block setups). |
| `label` | The field's label from the setup's VAR LABELS; blank where the setup gives none. |

The reader uses `name`, `start`, `end` and `type`; the other columns are for the tidier and for review.

## How the layouts were produced

The setup files use the card-image SPSS syntax of the early 1980s: a command name in columns 1-15 and its arguments from column 16, with a command ending where the next line has text in column 1.
In files that start with a `NUMBERED` command (`08297-0001`, `08297-0015`, `08297-0017`), columns 73-80 hold a card sequence number and are dropped before parsing.
`generate_layouts.R` then applies these rules, and stops rather than guessing if a setup breaks any of them:

- **Parsing.** Each DATA LIST block is read as a sequence of `NAME start-end [(format)]` entries after its header (`FIXED`, `(1)`, `/1`, `FILE=`, `RECORDS=1`); any other token, a `TO` range or a multi-record block stops the script.
- **Several blocks over one record.** `08297-0001-Setup.sps` has seven NORC blocks (flags and weights, base-year items, sophomore questionnaire, dropout, transfer and early-graduate questionnaires, tests) and `08297-0004-Setup.sps` three (flags and weights, base-year items, senior questionnaire), each written to build a separate SPSS file from the same record.
  They are merged into one layout: a field repeated in several blocks with the same name and columns is kept once, taking the one decimal count its definitions give (`FUWT`, `FUTESTWT` and `RAWWT` carry `(3)` only in block 1); any other repeat stops the script.
- **One erratum.** Block 2 of `08297-0001-Setup.sps` defines `BYTESTWT` at 137-144, the columns block 1 gives to `FUPARWT`.
  The codebook's record layout (`08297-0001-Codebook.pdf`, Appendix D, p. D-1) and its entry for question WT3 put `BYTESTWT` at 145-152 (F8.3), as block 1 does, so the block-2 entry is dropped.
- **Sub-fields of an ID.** The setups define the school and student parts of the case ID as separate overlapping fields (`SCHOOLID 4-7` and `STUDNTID 8-9` inside `CASEID 4-9`; `SCHLID 1-4` inside `ID 1-6`).
  The reader refuses overlapping fields, so a field lying wholly inside another is dropped and the enclosing ID is kept; the school ID is the first four characters of `CASEID` or `ID`.
  Any other overlap stops the script, and none occurs.
- **Senior teacher file.** The two teacher-comment files share one setup file written for the sophomore file, which tells the user to remove the sophomore-only variables (`TYB11A` to `TYB14`, columns 20-37) for the senior file; the senior layout keeps the 13 fields that lie within its 19-byte records.
- **Types.** Every file is first read with all fields as text, and a numeric field is typed `d` only if all its non-blank values are numbers.

## Checks

- Every record of each file has the same length, with LF line ends and no carriage returns, and each layout ends exactly at the last byte of its record, so the reader's record-width check passes.
- Fields are in ascending order and never overlap (checked by the script and again by the reader on every build).
- The student, twins, teacher and labour-market layouts cover every byte of the record; the 1982 sophomore, senior and school layouts leave 436, 393 and 164 bytes that no DATA LIST entry defines, and the language layout 5.
- Record counts equal the ICPSR manifests for all nine files.
- The 1982 files repeat the base-year items of every base-year participant, so they can be checked against the 1980 student file: for all 27,118 base-year participants in the sophomore file and all 11,500 in the senior file, `BB083` (sex), `BB048` (TV hours), `BB084` (age), `BB089` (race) and `BB085` (height) are identical.
- The 08896 `.sav` files carry most of the same variables for the follow-up subsamples, and agree field by field once the rescaling below is applied: all 1,219 shared fields of the 1982 senior file; 1,662 of the 1,704 shared fields of the 1982 sophomore file (38 have no values in common, and the others are `YB009C`, which the `.sav` holds as 0 for every case, and `BYWT`, `RAWWT` and `FSCHID`, which the later release revised); and 437 of the 439 fields the 1980 student file shares with the sophomore `.sav` (`YB009C` again, and `BB081E`, which the `.sav` recodes) and all 470 it shares with the senior `.sav`.
- Frequencies of `BB048` and `BB083` by grade, `LB14`, `TBB05` and `TBB10`, `TWINDATA`, `FY61`, `FD75`, `FE76`, the participation flags, `SCHURB` and the quartiles of `CUNEMR80` all equal the codebooks' tables (`BPIPD-1295_notes.md`, "Spec (2026-11-08)").

## Decimals

The decimal point is physically present in some fields and implied in others, and one file stores decimal fields rounded, so each field was measured rather than assumed.
`rescale_decimals` records the outcome; neither the reader nor `variables.csv` should rescale anything else.

- **Point present, nothing to rescale.** `DESIGNWT` in the 1980 student file (every value reads like ` 182.5544952748`), every weight in the 1982 files (`0119.801`) and the 1982 school file's `WEIGHT`, and the 1982 sophomore test scores `FY*FS`/`FY*SD` (`007.25`, two digits after the point although the setup says `(3)`).
- **Implied, divide by `10^rescale_decimals`.** The 1980 student file's composite scales `(2)`, SES composite and test scores `(3)` (44 fields), 34 composites and test scores in the 1982 sophomore file, 36 in the 1982 senior file and all 27 decimal fields of the labour-market file: no value contains a point.
  For example `BBSESRAW` reads `-0096` for -0.096, and its codebook entry says the missing code 98 is stored "with 3 zeroes at the right" (`98000`); `CUNEMR80` (F3.1) reads ` 97` for 9.7 per cent, and its quartiles after dividing by 10 equal the codebook's (1.4, 5.8, 7.2, 8.7, 24.9).
  Missing codes follow the same scale, so a tidier that rescales should apply its missing-value rules to the rescaled value (98, 998, 99.9 and so on).
- **A second erratum.** `08297-0004-Setup.sps` declares `(3)` for the five base-year composite scales `BBCONCPT`, `BBLOCUS`, `BBWORK`, `BBFAMILY` and `BBCOMMUN`, but the codebook's record layout gives F4.2 for each, the 1980 setup declares `(2)` for the same fields, and their raw digits equal the 1980 student file's for every matched senior; `rescale_decimals` is 2 for them while `decimals` keeps the setup's 3.
- **Rounded, nothing to rescale.** The twins and siblings file reuses the student file's setup, but it stores every decimal-format field rounded to a whole number on its natural scale: `DESIGNWT` reads `90` where the student file reads `90.2123524814`, and `BBSESRAW` reads `-1` for -0.981.
  For the 2,257 sampled twins and siblings who are also in the student file, every value of all 45 such fields lies within 0.5 of the student file's value, so `rescale_decimals` is blank throughout the twins layout and the student file is the precise source for those students.

## Values the tidier must handle

- **Identifiers.** The base-year `CASEID` and the follow-up `ID` are the same six-character key (school in characters 1-4, student in 5-6).
  The teacher-comment files carry `SCHOOLID` and `STUDNTID` separately, and the sophomore file writes student numbers below 10 with a leading blank, so the key is `SCHOOLID` followed by `STUDNTID` zero-padded to two digits; built that way, all 67,053 senior and 76,560 sophomore teacher records match a student of the right grade.
  In the twins file 335 `CASEID` values have blanks in place of zeros (`1287 4`); with blanks read as zeros all 616 sampled twins and 1,641 sampled siblings match the student file, and 17 of the 461 augmentation (non-sample) twins also share an ID with a student-file case.
- **The twins file's `.` code.** In the twins file the 117 senior-only (`EB`) fields hold `.` for sophomores and the 118 sophomore-only (`YB`) fields hold `.` for seniors, so those 235 fields are read as text; recode `.` to `NA` before converting them.
- **Names.** `TBB11C` in the sophomore teacher layout is the setup's spelling of `TYB11C` (its VAR LABELS and SAS cards call it `TYB11C`, "taught history or geography"), and the 42 monthly activity fields at the end of the 1982 senior record (`PSEJU80` to `JOBFE82`) have no label in the setup.

## Regenerating

Run from the repository root; it reads the study folder (read-only) and writes only into this folder:

```bash
Rscript harmonisation/datasets/BPIPD-1295/layouts/generate_layouts.R
```

It prints, for each layout, the fields dropped, the decimal findings and any non-numeric values, and a summary table.
Its peak memory is about 0.7 GB.
